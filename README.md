# FlameSync

A static, browser-local video studio for **flamesync.defencore.com**. Combine static-fire footage with a thrust and pressure CSV, trim the footage, align ignition, and download a video with telemetry rendered into its frames. The interface defaults to Ukrainian, with an English option in the header. Language changes apply immediately without resetting files, trimming, synchronization, or measurements. Reusable preferences and entered test metadata are stored locally on this device. Code comments and rendered video annotations remain English.

## Use

1. In **Project**, use **Add files** to choose video and CSV together, or drop both anywhere in the editor. Source and display units default to **kgf** for thrust and **bar** for pressure throughout the service. Here kgf means kilogram-force, often written as kg in test-stand logs. If the file uses other units, set them under **CSV format & units**. Motor model and test date are directly below the source files; expand **More test details** for logger, camera, and notes.
2. Select the video range with the trim handles or the **In / Out** controls. The **Video** inspector beside the preview shows the current source frame, its precise timestamp and interval, playback FPS, resolution, and CSV sample rate. **Set In** starts at the displayed frame; **Set Out** includes that frame. Expand **Source details** for the filename, codec, size, duration, and timing inspection.
3. The **Go to selected start** transport button (or **Home**) returns to the current **In** point and pauses playback, preserving trimming and synchronization. Pause at visible ignition, verify the suggested anchor under **Fine synchronization**, and click **Align ignition here**. Alignment pauses on the selected frame and waits for the final queued seek when scrubbing quickly. It maps that frame to the chosen CSV ignition while preserving the current duration percentage, including 200% slow-motion mappings. Repeated alignment at the same frame keeps the same offset. Refine with the offset field (microsecond precision), 10 ms buttons, or by dragging the CSV track.
4. **Full frame + data** keeps every part of the source visible, with separate thrust and pressure plots below and useful information beside the footage. The default output is **Full HD, 1920 × 1080, 16:9**, including for smaller sources. A/B burn markers and the original CSV burn duration appear by default when both boundaries are available. In **Project**, fill in the motor model, test date and ID, location, logger, sample rate, camera, and recording notes. Only populated fields appear; sample rate defaults to the average derived from the CSV. The side panel also shows peak values and total impulse. Choose a source, landscape, portrait, or square output frame; the source is always fitted without stretching or cropping. **Overlay on footage** puts the charts on the image instead. Adjust title, theme, height, pressure, and impulse to suit.
5. Click **Save video** in the header or the **Save your video** panel below the editor. Export defaults to **MP4 / H.264, Full HD 1920 × 1080, Very high quality**, with original frame timestamps. The panel explains which files or alignment are needed before saving and shows the selected format, duration, and dimensions when ready. **Format & quality** opens the export settings and focuses the format selector. Change format, resolution, quality, frame rate, and audio there. When creation finishes, the download starts automatically; the completed file can be downloaded again from the same visible save panel. The sample project includes clearly labeled synthetic footage, audio, and telemetry.

These instructions use the English labels. The header language selector switches between **UA** and **EN**. Ukrainian users follow **Файли й дані → Синхронізація й обрізка → Зберегти відео**; advanced timing correction and longer explanations remain in disclosures and information tooltips.

## Video templates and chart range

The first setting in **Appearance** is **Video template**. **Full frame + data** keeps the existing studio composition with charts below the footage and a separate test record. **Charts on video · stacked** fits the complete source image between a compact technical header and filename footer, places thrust and pressure vertically on a translucent panel, and overlays the motor record and results on the image. The header uses one horizontal line in landscape: source frame and native timestamp, log row and mapped time, then resolution, measured FPS/VFR status, and average log rate. Square and portrait outputs use two lines. Detailed frame intervals and input units remain in the editor; repeated category headings and CSV captions are omitted from this template. The stacked plots share one time axis. The footer lists the video, measured log, and optional theoretical file. **Overlay on footage** retains the compact bottom strip. The **Video template** shortcut below the editor opens the selector directly. Preview and exported frames use the same layout.

**Chart time range** defaults to **Burn interval · A/B** for every video template. The measured and theoretical burn intervals define the shared chart window, with an 8% margin on each side. Long idle sections cannot squeeze a short burn into the edge of the graph. If one profile has no reviewed A/B, its trace is clipped to the known burn window; if neither has usable boundaries, the complete source ranges are shown. **Entire CSV** explicitly shows all measured and mapped theoretical samples. Hiding the A/B annotations does not change chart focus. This setting never changes source measurements, duration, impulse, trimming, or synchronization.

The stacked template starts at 78% opacity and supports **0–95%**. Text retains its own dark outline and the curves use a contrast stroke independently of panel opacity, including over bright footage. The technical header and filename footer remain opaque. Its panel geometry and theme are fixed; height and light-theme controls remain available for the other templates. Pressure can be hidden without changing footage bounds. The output still defaults to **1920 × 1080, 16:9**.

Its narrower left cards separate the test record from **LIVE TOTALS**. Populated metadata wraps and grows vertically, reserving space above the live card. Live peaks and **IMPULSE SO FAR** always follow the current telemetry time, including rewind and gaps, regardless of a saved side-panel result preference. **FINAL RESULTS** above the graphs groups the complete log's peak thrust, peak pressure, and total impulse; A–B burn duration sits beside the curve legend. These final measurements do not change with playback or time stretch. The old duplicate impulse footer is removed. Hiding test details removes both result groups; the optional impulse control then shows one accumulated value in the graph header. The side-panel result selector is available in the other templates.

Use **Move video** above the preview to drag the footage into a useful position between the fixed data panels. While this mode is active, a 10% grid, cyan center axes, and an amber horizontal reference at 80% of the video area help center the motor and align its lower edge. A stronger green vertical guide marks the midpoint of the open space between the left data cards and the right graph panel. Hiding test details moves this guide to the center of the unobstructed area left of the graphs. The guides follow the displayed composition in fullscreen and portrait views; they stay outside the composition canvas and never appear in exports. **Appearance → Video position** provides horizontal and vertical offsets (−50% to +50% of the video area), scale (50–200%), and **Reset framing**. Arrow keys move the image by 1% while this mode has canvas focus; Shift moves by 5%. Escape during a drag or a cancelled pointer gesture restores that gesture's starting position; resizing the preview during a drag also cancels that gesture. By default, the complete image is centered and fitted; manual shifting or enlargement may move source edges outside the video area. The header and footer are protected by clipping. A validated replacement video resets placement to the complete centered image. These placement controls affect the stacked template only and never change frame selection, synchronization, telemetry, or the trim range.

## Saved preferences

Reusable settings save automatically on this browser/device: motor/date/test details, appearance and video placement, source/display units, export quality and format, analysis thresholds/display options, and preview playback options. Reloading restores these choices before controllers initialize. Loading the first video after a reload uses the restored placement; replacing an already open video resets its framing. Video and telemetry files must be selected again. Trim, synchronization, A/B, theoretical clock corrections, per-profile settings, and source file names are session-only.

**Clear settings** in the top bar resets metadata, appearance, export/analysis preferences, and language without reloading or discarding the loaded sources and their measured events. Active logs keep their original input-unit interpretation, and an open theoretical curve keeps its alignment and clock calibration; future imports use the default kgf/bar settings and ignition alignment. Reset is unavailable while an import, analysis, or export is running. Changes are saved after a short debounce and flushed when the page closes; incomplete drags are not saved. Blocked browser storage leaves the editor usable and shows a local notice. No preference data is uploaded.

## Compare burn profiles

Open **Burn profile analysis** beside **Video editor** to work with CSV logs independently of the video project. Add or drop up to 50 logs (20 MB per file, 100 MB total). Choose source units for new imports or change an individual profile's units. Millisecond, microsecond, second, and nonzero logger clocks are compared by timestamp; unequal acquisition rates are never matched by row number.

The initial 5% peak threshold suggests the first observed ignition and final burnout. Review the A/B source times, enter exact values, or select a profile and pick/drag its markers on the graph. Missing observed events remain blank. **Ignition at zero** and **Burnout at zero** shift the display clock; **Both events · 0–100%** maps each selected burn to burn phase for shape comparison. These views never change the original duration, impulse, or specific impulse. Use the wheel to zoom, drag to pan, and double-click or **Fit profiles** to fit. Thrust and pressure have separate plots and independent value axes; both plots and the difference chart share their visible time window.

Choose a reference profile to inspect candidate-minus-reference curves, time-weighted RMSE, mean difference, and impulse change. Differences use raw measurements only on the common selected burn interval, with interpolation within valid source segments and no extrapolation across missing intervals. The table retains original physical metrics even when display units or chart alignment change.

**Moving mean** and **Trend residual** views help examine signal variation. Residual RMS uses a centered time-window mean (100 ms initially), integrated over the middle 80% of the selected burn. Each profile can use a custom noise interval in original CSV seconds, including a baseline interval. Complete source-window support is required; missing data and unsupported edges are excluded. Residual includes real combustion fluctuations and measurement noise, so it is not calibrated sensor uncertainty or a sample-rate-independent sensor specification. Different bandwidths and logger processing still affect comparisons.

Enter consumed propellant in grams to calculate measured **specific impulse** as `I / (m × 9.80665)`, with mass converted to kilograms. Without mass or with missing burn coverage, specific impulse remains unavailable. Thrust and pressure alone do not establish thermal efficiency. See [NASA's specific impulse explanation](https://www1.grc.nasa.gov/beginners-guide-to-aeronautics/specific-impulse/). Impulse integrates positive thrust; mean thrust retains the signed measured force over covered time. **Export comparison CSV** saves the original SI values, selected events, difference metrics, and method settings locally. Synthetic comparison examples are generated only when requested.

Analysis runs in a dedicated worker; original logs remain there while bounded, extrema-preserving curves are sent to the UI. Both workspaces retain their independent state when switching tabs. Video playback pauses on entering analysis, and video editing shortcuts are inactive there. Files and analysis are discarded when the tab reloads.

## Batch / series variation

In the analysis workspace, change **Analysis mode** to **Batch / series variation**. Add CSV files together or choose **Add a folder of CSV logs**; folder import selects CSV, TSV, and TXT files only. An optional series name identifies the downloaded report. **Compare examples** generates five synthetic tests in memory in this mode. Both analysis modes share their source files, source units, and reviewed burn events.

Every included test has equal weight, independently of its sampling rate and duration. A test needs valid ignition/burnout and complete coverage of its selected burn to enter series statistics. Missing or invalid tests remain listed with an exclusion reason. Each metric shows its own valid sample count: for example, specific impulse omits tests without a supplied propellant mass. The **Include in series statistics** checkbox controls membership. Hiding a curve changes the plot only; it never silently removes its measurements from the series.

The mean profile uses the common aligned burn interval. Choose ignition, burnout, original logger time, or normalized 0–100% burn phase. Normalization changes the shape comparison clock only; scalar statistics retain original source seconds. The spread band shows the sample mean ± one sample standard deviation, or minimum–maximum. It describes variation among the loaded tests, without implying a confidence interval or acceptance tolerance. Initially the graph shows the mean and selected test; **Show individual profiles** reveals the other visible curves. The lower graph shows each visible test minus the series mean. Bounded display curves retain original knot/extrema samples; report metrics are calculated separately from the original selected-interval measurements.

The summary reports arithmetic mean, sample standard deviation (divisor `n − 1`), coefficient of variation `100 × SD / |mean|`, minimum, and maximum for burn duration, impulse, mean/peak thrust and pressure, residual noise, and specific impulse. One test cannot estimate SD; relative statistics remain unavailable near zero mean. Per-test deviations report the original value, difference and percentage from the series mean, and standardized score where SD is positive. **Potential outlier** marks values outside Tukey's 1.5 IQR fences from at least five valid observations, using R7 interpolated quartiles. The flag invites review and never automatically excludes a result. A small scale-relative numerical tolerance prevents integration roundoff from flagging nominally equal tests.

**Export series report CSV** saves canonical SI statistics, median, per-test deviations/flags, membership, exclusion reasons, source units, alignment, detection threshold, noise window, and series name. No report or source file is uploaded or retained after a reload. Statistical definitions follow NIST's [sample standard deviation](https://www.itl.nist.gov/div898/software/dataplot/refman2/auxillar/trimsd.htm), [coefficient of variation](https://itl.nist.gov/div898/software/dataplot/refman2/auxillar/coefvari.htm), [box-plot fences](https://www.itl.nist.gov/div898/handbook/eda/section3/boxplot.htm), and [percentile methods](https://itl.nist.gov/div898/handbook/prc/section2/prc262.htm); the implementation's quartile convention and minimum flagging sample size are explicit above.

## Optional theoretical profile

Expand **Theoretical profile · optional CSV** above either workspace and choose **Add theoretical CSV** to load a simulation or calculation. The file uses the same three required time, thrust, and pressure columns as measured logs, with a 20 MB limit. Its source units are independent of measured files and default to kgf/bar. Review the automatically detected theoretical A/B source times, enter manual boundaries, or use **Detect burn** to detect them again. Missing observed boundaries remain unavailable. **Show theory** controls the shared theoretical reference in video, individual comparisons, and series analysis; the theoretical file never becomes a measured test or a member of the batch statistics.

In analysis, the theoretical trace uses the workspace's selected clock alignment. Raw, moving-mean, and residual views apply the same moving-window width to measured and theoretical traces. **Measured versus theory** reports each test's original impulse and duration percentage differences, time-weighted thrust/pressure RMSE, mean thrust error, and common-interval coverage. Error calculations use raw data only on the common selected burn interval and do not bridge gaps or extrapolate. Normalized burn phase changes the displayed shape comparison, while source duration and impulse stay unchanged. **Export theory comparison CSV** saves the comparison and original canonical values locally.

**Theoretical timing in video** affects only the video's theoretical trace. **Match ignition** is the default; **Match burnout** shifts the end event, **Match both events · retime theory** explicitly fits both boundaries, and **Original CSV time** preserves the source clock. Extra offset shifts the theory in measured CSV seconds. The duration percentage multiplies that alignment's time scale, anchored at measured A when available. These controls never change original theoretical sensor values, duration, or impulse. Video preview and both export formats use the same optional theory renderer.

Invalid source units or A/B edits suspend the theoretical comparison until corrected. Invalid video-only timing blocks saving an enabled theoretical overlay but leaves valid theoretical data available to analysis under its own alignment. If the selected video alignment lacks required burn anchors, saving waits for reviewed A/B markers, original CSV time alignment, or disabling theory. An invalid replacement file retains the last valid reference. All parsing and analysis stay on the device; removal or a tab reload discards the theoretical source.

## Timeline editing

The timeline has its own visible time window. **+ / −** zoom around the playhead, **Fit video** shows the complete source, and **Fit selection** shows the In/Out range. The scrollbar pans a zoomed window. Click or drag the video track or ruler to seek; Alt + wheel zooms at the pointer, while Shift + wheel or horizontal scrolling pans. Zoom and pan change the view only and never retime or trim the export.

**Snap** is on by default: trim handles snap to actual frame presentation boundaries, and CSV dragging aligns its start, ignition, or end near the playhead, trim edges, or source endpoints. Hold **Alt** to bypass snapping temporarily. Exact numeric trim and offset fields retain the entered seconds. A narrow selection can be enlarged with **Fit selection** for precise editing. **Loop** repeatedly plays the selected range for visual comparison.

**Undo / Redo** covers trim points, telemetry offset, time scale, and chosen CSV anchors. A complete drag is one undo step; **Escape**, pointer cancellation, and lost capture roll back the entire gesture. History stores at most 100 numeric snapshots, independently of media size. A replacement video resets obsolete edit history and alignment while keeping the chosen events in the current CSV; a new CSV or reinterpreted CSV time unit resets its clock and anchors. **Clear trim** restores the complete video while retaining synchronization. **Reset edits** resets trimming and synchronization together and can be undone.

All frame-derived actions (In/Out, ignition/end alignment, and event capture) pause and wait for the final requested source frame. Out is exclusive for export; previewing the Out edge or reaching the selected end shows the last included frame. Invalid CSV anchor drafts remain visible with a validation message, disable the corresponding alignment actions, and leave the applied mapping/history unchanged.

Keyboard controls outside editable fields: **Space** play/pause, **Left / Right** step one source frame, **Shift + Left / Right** step ten, **Home / End** go to the first/last included frame, **I / O** mark In/Out, **S** align ignition, **+ / −** zoom, **F** fit selection, **\*\* fit video, **Ctrl/Cmd + Z** undo, **Ctrl/Cmd + Shift + Z** or **Ctrl + Y\*\* redo. Text fields retain their native editing shortcuts. Character commands also recognize physical keys when using a Ukrainian keyboard layout.

## Video presentation

The full-frame layout keeps the source uncropped, reserves a separate bottom region for telemetry, and uses the side region for context. Thrust and pressure occupy separate plots with independent axes: compact landscape panels place them side by side, while portrait or taller panels stack them. Current thrust, pressure, logger time, and optional impulse sit in their own values region. The model and ISO date lead the sidebar, followed by live totals or final results, source-frame/log diagnostics, and populated test details. A single heading identifies whether peaks and impulse are still accumulating. A/B boundaries mark each signal plot, with **Burn duration** shown in original CSV seconds; they are enabled by default when both boundaries are available. Optional theory uses a distinct dashed trace on both plots.

The same geometry and renderer are used by preview and export. Metadata wrapping is cached per canvas; current values and source frame/log positions remain live. Long records, portrait/square/ultrawide frames, pressure plus impulse, and the minimum panel height are covered by layout checks. Empty metadata fields are omitted.

## CSV contract

```csv
time_ms;thrust;pressure
0;0.4;0.0
16;0.4;0.0
33;0.4;0.0
```

Semicolon, comma, and tab delimiters are supported. Semicolon or tab separated files may use decimal commas. UTF-8 BOM, quoted individual fields, reordered named columns, blank lines, and `#` / `//` comment lines are supported. Selected sensor values must be numeric and timestamps must increase strictly within each channel; unused columns may contain text. Time is explicit: **time_ms** means milliseconds, **time_us** (also time*µs/time*μs) means microseconds, and **time_s** means seconds. A generic **time** column opens the column dialog to choose its unit; the same unit can also be set under **Project → CSV format & units**. The time-unit selector can also override a mislabeled header. Numeric magnitude is never used to guess units; every timeline calculation uses normalized seconds. Reinterpreting the time unit resets synchronization and A/B measurement. A video project's measured CSV may be up to 50 MB; analysis and theoretical CSVs are limited to 20 MB per file, with a 100 MB total for measured analysis logs. Malformed rows produce an explicit line-numbered error rather than being silently skipped.

### Custom columns and independent sensor clocks

Unknown column layouts open **CSV columns** automatically. Use **Columns…** beside the video log, theoretical source, or profile to review or change an existing mapping. The preview shows original physical line numbers and the first five rows. Column choices use physical indices, so duplicate names remain distinguishable. Turn off **First row contains column names** for headerless files; the first reading is then retained.

Choose a thrust time/value pair and an optional pressure time/value pair. Pressure may share the thrust clock or use another column and another time unit. Each channel keeps its native timestamps, readings, rows, gaps, and acquisition rate; pressure is never resampled onto the thrust clock for statistics or noise. Absolute timestamps remain unchanged and both clocks must refer to the same time origin. Missing pressure displays as unavailable rather than zero. **Allow empty samples** treats blank selected values as no new reading for that channel, while any recorded value still requires a valid timestamp. Long missing intervals are never interpolated. The full chart includes both source ranges; A/B validation and synchronization remain tied to the thrust clock.

Burn boundaries can use **Automatic detection**, an **Active state** column (`0 → 1 → 0`, also `false/true`), or **Separate start/end flags**. Explicit events use the selected thrust time column and exact row timestamps. Missing endpoints stay unset for manual correction. Multiple periods span the first ignition through the final completed burnout; an unfinished final period cannot reuse an earlier burnout. Selecting a new time column or time unit resets the video/log mapping. Changing only pressure keeps synchronization and thrust A/B; changing the thrust value column or event columns recalculates A/B while preserving the video clock mapping.

Profile batches reuse a mapping only for the same header layout within the current tab. Each loaded profile can be remapped independently. Report CSVs include the one-based source column indices, separate time units, channel counts/ranges, and pressure coverage. No filenames, readings, column mappings, or sample clocks are written to browser preferences or uploaded. Canceling or rejecting a replacement retains the last usable source; later unit changes apply to that visible source.

Set **CSV thrust** and **CSV pressure** to the actual recorded units in Project. Set **Thrust unit** and **Pressure unit** under **Appearance → Video units** for the converted output. Source and output units initially use **kgf + bar** in the editor, profile comparisons, series, and theoretical imports. Values, both chart axes, peaks, and impulse use the selected output units in preview and export. Force supports N, kN, kgf, gf, and lbf; pressure supports Pa, kPa, MPa, bar, psi, and atm. Conversion factors follow [NIST SP 811](https://www.nist.gov/pml/special-publication-811/nist-guide-si-appendix-b-conversion-factors/nist-guide-si-appendix-b9). Input is normalized once to N and bar; changing output units does not reparse the log, alter synchronization, smooth data, or change the baseline. Reinterpreting source force or pressure units preserves timing and manual measurement markers. Impulse uses the selected thrust unit multiplied by original logger seconds. Video, profile, and theoretical impulse use the same exact positive area of each linear thrust segment, including zero crossings from a negative baseline. A gap is longer than the greater of **0.5 seconds or three typical logger intervals** (a bounded median estimate), so low-rate logging remains valid. No interpolation or integration is performed across these gaps. Impulse after a gap is the sum of the measured intervals only. The suggested ignition is the interpolated first crossing of 5% of peak thrust and should be visually verified. Generated video/profile/series example CSVs use kgf/bar too, with their original physical force values preserved.

Synchronization uses `csvTime = (originalVideoTime - offset) / timeScale`, with `timeScale = 1` for ordinary editing. A positive offset moves the CSV later. The PLAYHEAD thumb and VIDEO / CSV LOG cursor share the same time axis, including the slider thumb radius, on desktop and mobile. The original CSV clock is retained, including a nonzero first sample. Trimming does not change alignment. The same Canvas renderer is used for preview and export; future curves may be faintly visible or hidden. There are independent labeled thrust and pressure scales. Values outside the log and inside data gaps show an em dash.

Video and telemetry do not need matching rates: 120 FPS footage and a 50 Hz CSV are both evaluated in seconds, with interpolation between valid CSV samples. High or variable FPS never automatically stretches the log. In particular, ordinary 60 FPS footage does not need 200% telemetry duration just because it has twice as many frames as 30 FPS footage. **Match source** keeps the original frame timestamps; choosing a fixed export FPS resamples frames while preserving duration and telemetry time. Slow-motion files may play at a different rate from their capture rate; the file playback clock is authoritative. Use explicit time stretch or two-event alignment when intentionally mapping real-time telemetry to slow-motion playback.

The full-frame bottom panel shows instantaneous thrust and pressure, while the source strip retains the CSV clock. **Appearance → Result values** chooses **Live totals** (impulse and peaks reached up to the current frame) or **Final results** (the complete CSV) for the full-frame side panel. Live totals rewind correctly, retain the last known values during data gaps, and become final results when the log ends. The chart cursor follows the CSV clock. Accumulated impulse can optionally also be shown in the bottom panel.

The right panel leads with the tested motor from **Project → Motor model** and its test date in **YYYY-MM-DD**, followed by the results and the populated test record. Test ID, location, logger, log rate, camera, and notes each retain a visible field. Values wrap within their own measured bounds; an exceptionally long value ends with an ellipsis when an explicitly compact output cannot fit it. Whole fields are never silently omitted, and canvas text is not horizontally condensed.

A fixed two-row source strip below the graph groups **VIDEO** filename, source frame, precise video timestamp, FPS/resolution and **LOG** filename, physical CSV row, original CSV time and measured sample rate. Long filenames retain their beginning and extension. These diagnostics use the same source clocks in preview and export, including slow motion and interpolated samples.

The standard Full HD composition reserves **1440 × 810** for 16:9 footage, a right column for test information, and the bottom quarter for the separate plots, instantaneous values, and source strip. Importing files, adding metadata, or switching pressure, impulse, theory, and test details never changes the video rectangle or reserved telemetry region. Only an explicit template, output-frame, or panel-height adjustment changes the composition. Hiding test details leaves their reserved area available rather than resizing the footage. The stacked on-video template reserves a 42 px technical header and 42 px filename footer at Full HD, fitting footage into the remaining full-width area by default; explicit framing controls reposition or scale it within that area.

The chart uses rounded axes in the selected output units, consistent thrust/pressure colors, and a cursor with sample markers. Until a CSV is loaded it displays **Waiting for CSV data** and empty values. The editor does not substitute example measurements for the user's footage. Preview and export share the same geometry and renderer.

## Measure telemetry

Open **Measure telemetry** below the preview. This tool works with a CSV alone. Drag A and B onto the thrust rise and decay, click the chart to move the nearest marker, or enter exact CSV seconds. Arrow keys on a marker follow actual CSV samples; Home / End move to the log boundaries. The result is the elapsed interval in original logger seconds.

**Detect burn** interpolates the first rise and final decay through the selected percentage of peak thrust (5% by default). Missing baseline samples, gaps at crossings, and incomplete burns are reported; an unobserved boundary stays blank until set manually. Multiple pulses are measured from the first rise to the final decay, including the pause. Gaps inside a selected interval are included in elapsed time and flagged. This is a threshold-based measurement, so verify or adjust the markers for the test being analyzed.

**Use A/B as sync events** fills the ignition and end CSV anchors without changing alignment or trimming. With time stretch active, the tool also shows the corresponding video duration while keeping the CSV measurement unchanged. **Show measured interval in the video** is on by default: when both boundaries are available, A/B appear on each signal plot and **Burn duration** retains the elapsed original CSV seconds in both preview and export, including during slow-motion alignment. Missing boundaries are not invented.

## Optional time stretch for analysis

**Advanced · telemetry time stretch** is collapsed by default. Telemetry duration accepts **10–1000%**, with 0.001% input precision. 100% keeps the original timing; 200% maps each logger second to two video seconds. Changing the percentage keeps the selected CSV anchor at the same video frame. Dragging the CSV track shifts it; dragging its right edge in advanced mode changes duration while keeping the first CSV sample fixed. Reset to 100% preserves the selected anchor. Reset on the timeline restores the full video, original timing, and zero offset. Loading a replacement source also resets synchronization.

**Align the end** is the quick two-point workflow: first use **Align ignition here**, pause at the matching end in the video, then click **Align end here** in Advanced. It calculates Telemetry duration and keeps the aligned ignition fixed. **CSV end event** defaults to the last sample; enter the burnout time if the CSV has a tail. Reversed events, out-of-range CSV times, and unsupported scales leave the mapping unchanged. **Go to aligned ignition** jumps to the current synchronization anchor, including its offset and stretch.

For a logger timing error, clock drift, or slow-motion mapping, open **Match two events**. Enter original CSV times for A and B, navigate to each corresponding video event, and use **Use playhead**. **CSV interval**, **Video interval**, and **Required duration** compare the selected events before applying a fit. For example, a 1-second CSV interval matched to a 2-second video interval requires 200%; that ratio alone does not identify which device recorded time incorrectly. **Fit both events** solves offset and duration together. Both points must be within the source ranges, in chronological order, and produce a scale in the supported range. Invalid fits leave the current mapping intact. Closing advanced controls keeps the mapping active; its percentage remains visible in the summary.

The video and audio are never retimed. Sensor amplitudes, the chart's CSV clock, and impulse integration retain the original logger time. Any non-default scale is labeled **TIME STRETCH** on preview and exported frames, including when the test side panel is hidden. This is a global linear time correction; it does not repair missing samples or apply local/nonlinear warping.

The focused telemetry track supports Left / Right for 10 ms offset changes (Shift for 1 ms); its stretch handle supports 1% duration steps.

```sh
npm ci
npm run dev
npm test
npm run typecheck
npm run build
```

## Export and privacy

Mediabunny and browser WebCodecs decode, composite, and encode frames in a dedicated worker. Exports do not record the preview in real time, so playback speed and monitor refresh rate do not affect the result. Audio and video are both trimmed on the same original timeline. If requested audio cannot be encoded, export reports an error rather than silently removing it. A dedicated worker scans every frame presentation timestamp without decoding the video payload. The editor displays measured playback FPS, total frame count, constant/variable timing, and average CSV sample rate. The right-side Video inspector uses one-based source frame numbers in presentation order, with timestamps shown to six decimal places. Below the frame counter, **CSV row** identifies physical lines in the original file, counting headers, blank lines, and comments. Between samples it shows both rows and the interpolation percentage; the mapped CSV clock is displayed in the original time unit. Before/after-log positions and data gaps have explicit statuses. This lookup uses absolute logger time, offset, and time stretch; it never pairs a row with a frame by index. Frame numbers retain their source positions after trimming; Out is exclusive and its button uses the end of the displayed frame. The full-frame export side panel also includes the source frame and timestamp. Capture FPS is not inferred from playback FPS because slow-motion files may store a different playback clock. Frame stepping follows the indexed presentation times, including VFR and fractional frame rates; it does not assume 30 FPS. The lookup tolerates browser microsecond timestamp rounding, and native seeks land just inside the chosen frame so decoding cannot round back to the preceding image. The logical frame timestamp remains the original source PTS, so repeated next/previous steps keep advancing without retiming telemetry. The first/last source-frame buttons disable at their respective boundaries. Export retains original frame timestamps when **Match source** is selected.

Export needs WebCodecs, OffscreenCanvas, and codecs supported by the browser and OS. Recent Chrome / Edge are recommended; Safari support depends on its version and OS codecs. Unsupported inputs or outputs are reported with an actionable message. MP4 uses H.264 / AAC; WebM uses VP9 / Opus. Compatible audio is copied when exact timestamps can be preserved; otherwise it is re-encoded. Re-encoding may add a short codec padding tail. Try the other output format if an encoder is unavailable.

Files are read through local Blob URLs. No video or CSV is sent over the network. Dependencies are bundled and hosted with the site; there are no CDN imports, external fonts, analytics, accounts, API keys, or upload endpoints. The Content Security Policy limits connections to the site itself and localhost development sockets. Edits and source files live only in the current tab and are not retained after a reload. Validated reusable preferences, interface language, and entered metadata are kept in local storage on this device. Source filenames, media, parsed samples, per-file events, trimming, and clock mappings are never stored. Clear settings in the top bar removes only FlameSync preferences and restores defaults in place, preserving loaded files and their input-unit interpretation. Encoded output is buffered in memory, so large or high-resolution exports require enough RAM. Canceling terminates the worker and discards the unfinished output. The completed output remains downloadable until replaced or the tab is closed.
